# Ask Korah — AI Chat Panel (`questions.html`)

In-page AI tutor sidebar that lets students ask questions about the current SAT problem and view step-by-step explanations. Lives entirely inside `korah-bot/sat/questions.html` as an inline `<script>` block (lines 689–1244).

---

## Architecture Overview

```
questions.html
└── Ask Korah Panel (#askKorahPanel)
    ├── Chat tab         — conversational Q&A, streamed
    ├── Explanation tab  — step-by-step worked solution
    │   ├── Korah source — generated by Gemini, cached in Firestore
    │   └── CB source    — CollegeBoard rationale (static, from question data)
    └── Math hand-off    — navigates to math-chat.html with context stashed
```

**API:** `POST /api/gem-proxy` (model: `gemini-2.5-flash`, streaming SSE)  
**Auth gate:** panel only activates after `korahReady` fires (Firebase auth confirmed)  
**Firestore cache:** explanations are persisted per question ID so repeat opens are instant

## Opening / Closing the Panel

| Trigger | Action |
|---|---|
| "Ask Korah" footer button (`#askKorahBtn`) | Opens panel, reads current question |
| "Explanation" nav button (`#showExplanationBtn`) | Opens panel and switches to Explanation tab |
| Close button (`#askKorahCloseBtn`) or `Escape` | Closes panel |

When opened, `body.ask-korah-open` is toggled, which pushes the topbar, footer, and main content area left by `--ask-korah-w` (26.25rem desktop / 100vw mobile). On mobile the main content is hidden entirely while the panel is open.

## Question Context

Every API call is prefixed with a context block built from the currently displayed question.

### `readCurrentQuestion()`

Reads question state in priority order:
1. `window.KorahSATPlayer.getCurrentQuestion()` — live player object (authoritative)
2. DOM fallback — scrapes `#questionNumber`, `#questionDomain`, `#questionParagraph`, `#questionStem`

Returns:

```js
{
  id,          // stable cache key: detailKey || id || derived hash
  number,      // display number string ("Question 3 of 45")
  domain,      // e.g. "Algebra", "Craft and Structure"
  passage,     // stimulus/paragraph text (reading questions)
  stem,        // question text
  options,     // [{ key: "A", text: "..." }, ...]
  correct,     // correct answer key or numeric string
  cbExplain,   // CollegeBoard rationale HTML
  type,        // "mcq" | "spr"
  isMath,      // true when calculator button is visible and enabled
  svgs         // serialized inline SVG figures (geometry diagrams, charts)
}
```

### `collectQuestionSvgs()`

Serializes figure-sized SVGs (≥40×40px) from `.sat-passage-card` and `#answerChoices` into XML strings so the model receives actual diagram content rather than placeholder text.

### `buildQuestionContextBlock(q)`

Assembles the plain-text context injected into every system/user prompt:

```
Section: SAT Math
Domain: Algebra
Passage: <stimulus text if present>
Question: <stem>
Choices:
  A) ...
  B) ...
Correct answer: B
Figures (1 inline SVG; ...):
--- figure 1 ---
<svg ...>
```

## Chat Tab

Conversational Q&A with message history scoped to the current question. History resets when the user navigates to a different question.

### System prompt

```
You are Korah, an SAT tutor. The student is working on a specific SAT question and wants help.
Be concise, encouraging, and use clear step-by-step reasoning.
Use Markdown for structure and KaTeX ($inline$ or $$display$$) for any math.
Never reveal the correct answer letter unless the student explicitly asks for it.

=== CURRENT QUESTION ===
<buildQuestionContextBlock output>
```

### Message flow

1. User types in `#askKorahInput` and submits (Enter or send button)
2. User message appended to `#askKorahMessages` and pushed to `chatHistory`
3. Streaming assistant message element created immediately (shows `…` while loading)
4. `callAPI()` fires with full chat history as `messages` and system prompt
5. Each SSE chunk re-renders the assistant bubble via `renderMarkdownAndMath()`
6. On completion, final reply pushed to `chatHistory` as `{ role: 'assistant', content }`

### Suggestion chips

Pre-filled prompts wired to the input field:
- "Explain this step by step"
- "What's the best strategy for this?"
- "Open Desmos visualizer in Math Chat" *(math questions only, triggers hand-off)*

## Explanation Tab

Generates and displays a structured step-by-step solution. Supports two sources toggled by a pill selector.

### Korah Explanation (AI-generated)

Cache lookup order on each tab open:

1. **In-memory** — `cachedKorahExplanation` (survives panel close/reopen within same page load)
2. **Firestore** — `KorahDB.getSatExplanation(questionId)` (persists across sessions)
3. **Generate** — calls Gemini if both caches miss

#### Generation system prompt

Instructs the model to return **only** a raw JSON object (no code fences):

```json
{
  "answer": "B",
  "summary": "one-sentence takeaway",
  "steps": [
    { "title": "Step 1 — Identify the equation", "body": "markdown + KaTeX" },
    ...
  ]
}
```

Rules enforced in the prompt: 3–6 steps, KaTeX for every variable/equation, first step restates the problem, last step states the answer.

#### JSON parsing (`parseExplanationJSON`)

Two-pass parser:
1. `JSON.parse` on the stripped string
2. Balanced-brace extraction fallback for cases where the model adds surrounding prose

#### Firestore persistence

On successful generation, the result is written via `KorahDB.setSatExplanation(questionId, payload)`:

```js
{
  answer:       "B",
  summary:      "...",
  steps:        [...],
  model:        "gemini-2.5-flash",
  questionStem: "<first 500 chars of stem>"
}
```

### CollegeBoard Explanation

Renders `currentQ.cbExplain` (raw HTML from the CB API) through `renderMarkdownAndMath()`. Shows a fallback message when the field is empty.

## Math Hand-off

When a Math question is active, the "Open Desmos visualizer in Math Chat" chip stashes the full question context in `sessionStorage` and navigates to `./math-chat.html#handoff`.

Payload stored at `sessionStorage.korahSatHandoff`:

```js
{
  from:         "sat-questions",
  questionId,
  domain,
  stem,
  passage,
  options,
  correct,
  svgs,
  contextBlock, // pre-built buildQuestionContextBlock string
  createdAt     // Date.now() timestamp
}
```

`math-chat.html` reads this key on load and seeds its first model call with the full problem context so the student can explore the solution in Desmos without re-entering the question.

## Streaming API (`callAPI`)

```js
callAPI(userContent, onChunk, { systemPrompt, temperature, messages })
```

- Sends `POST /api/gem-proxy` with `{ model, temperature, messages, stream: true }`
- Header: `X-Korah-Phase: sat-ask-korah`
- Reads SSE stream, parses `data:` lines, calls `onChunk(delta, fullSoFar)` on each token
- Returns the complete response string when the stream ends
- Throws on non-2xx status or empty response

---

## Rendering (`renderMarkdownAndMath`)

All model output goes through a three-step pipeline:

1. **`normalizeMathDelimiters`** — converts `\(...\)` → `$...$`, `\[...\]` → `$$...$$`, backtick-wrapped LaTeX-looking expressions → `$...$`
2. **`marked.parse`** — Markdown → HTML (falls back to newline→`<br>` if marked unavailable)
3. **`DOMPurify.sanitize`** — strips unsafe HTML before injection
4. **`renderMathInElement`** (KaTeX auto-render) — renders all `$` and `$$` delimiters

## State Variables

| Variable | Scope | Description |
|---|---|---|
| `currentQ` | Panel lifetime | Question snapshot taken at open time |
| `lastQuestionId` | Panel lifetime | Detects question change to reset state |
| `chatHistory` | Per question | `[{ role, content }]` array for multi-turn chat |
| `activeTab` | Panel lifetime | `'chat'` \| `'explanation'` |
| `explainSource` | Panel lifetime | `'korah'` \| `'cb'` |
| `explanationLoaded` | Per question | True once Korah explanation rendered (prevents re-fetch) |
| `explanationLoading` | Request | Mutex — prevents concurrent explanation generation |
| `cachedKorahExplanation` | Per question | In-memory copy of last generated/fetched explanation |

State for `chatHistory`, `explanationLoaded`, and `cachedKorahExplanation` resets whenever `currentQ.id !== lastQuestionId` (i.e., question changed between opens).

## Mobile Behavior

At ≤768px (`--ask-korah-w: 100vw`):
- Panel covers the full viewport
- Topbar, footer, and `#main-area-wrapper` are hidden while the panel is open (`display: none`)
- Closing the panel restores the full layout
